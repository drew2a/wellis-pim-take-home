# Export notes — from the previous team

This is everything we could reconstruct about the legacy export. It is incomplete;
treat these notes as hints, not guarantees.

## Column reference (what the fields were *supposed* to mean)

### patients.csv — one row per patient record in the old system

| Column | Intended meaning |
|---|---|
| `legacy_id` | Auto-generated row id from the old tool. Referenced by `intakes.csv` and `consents.jsonl`. |
| `full_name` | As typed by the patient or ops. |
| `email` | Primary contact; also used as login by one of the later automations. |
| `dob` | Date of birth. |
| `sex` | Whatever the form or the ops person entered at the time. |
| `bsn` | Dutch citizen service number, collected during the insurance experiments. Never validated. |
| `phone` | Contact number, format never enforced. |
| `city` | Self-reported. |
| `weight` / `weight_unit` | Weight at signup. Unit column added late and backfilled "where obvious". |
| `height_cm` | Height at signup; always intended as centimetres. |
| `status` | Where the patient stands commercially: roughly active / paused / churned / prospect, spelled many ways. |
| `signup_date` | When the row was created. |
| `source` | Which funnel created the row (`typeform`, `website`, campaign tags, `import` = a bulk load nobody remembers well). |

### intakes.csv — one row per submitted medical intake questionnaire

| Column | Intended meaning |
|---|---|
| `intake_id` | Form tool submission id. |
| `legacy_patient_id` | Should reference `patients.csv:legacy_id`. |
| `submitted_at` | Submission date. |
| `questionnaire_version` | Which version of the questionnaire; labelling discipline varied. |
| `weight` / `height` | **Self-reported at submission time** — not copied from the patient row, so they can legitimately differ from patients.csv. |
| `meds_current` | Free-text "what medication do you currently use". Never normalised. |
| `conditions` | Free-text relevant conditions/history, Dutch and English mixed. |
| `alcohol_units_week` | Self-reported units per week. |
| `outcome` | What happened to this intake medically (approved / rejected / pending — spelled many ways). Distinct from the patient-level `status`. |
| `reviewer_note` | Free-text note by the reviewing doctor, if any. |

### consents.jsonl — append-only consent event log

| Field | Intended meaning |
|---|---|
| `patient_legacy_id` | References `patients.csv:legacy_id`. |
| `type` | Consent type; only `data_processing` exists in this export. |
| `action` | `granted` or `revoked`. |
| `at` | Event timestamp (widget-side). |
| `version` | Consent-text version the patient saw. |

## Known caveats

- `patients.csv` is the patient table from the old spreadsheet-database. `legacy_id`
  was auto-generated by the tool. Several automations wrote to this table over the
  years, plus occasional manual edits by the ops team.
- `intakes.csv` came from the form tool via automation glue. `legacy_patient_id`
  *should* reference `patients.csv`, but the automation occasionally fired before the
  patient row existed.
- `consents.jsonl` is the event log from the consent widget. One JSON object per line,
  append-only. Believed complete from 2023 onwards; before that, nobody is sure.
- Dates: the form tool was set to ISO at some point in 2024. Before that, it depended
  on which automation wrote the row, and at least one of them was configured
  US-style. Nobody remembers exactly when what changed.
- Weights are "probably kilograms" but an early campaign targeted expats and the form
  briefly had a pounds option. The unit column was added later and backfilled "where
  obvious."
- `status` values were typed by different automations and different humans over time.
- BSNs were collected for a period for insurance experiments, then the field was
  hidden from the form; values were never validated.
- The ops team says: "some people definitely signed up twice with different emails to
  retry the intake."
